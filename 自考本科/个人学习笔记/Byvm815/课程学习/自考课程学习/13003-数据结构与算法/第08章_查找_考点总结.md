## 二、查找的基本概念

### （一）识记

| 术语 | 含义 |
|---|---|
| **查找（检索）** | 在查找表中确定是否存在关键字等于给定值的记录，并给出其位置/信息 |
| **单值查找 / 范围查找** | 查找某一个关键字值的记录 / 查找关键字在某个范围内的所有记录 |
| **查找表** | 由同一类型（记录）构成的集合；分**静态查找表**（只查不改）与**动态查找表**（可插入删除） |
| **成功查找 / 不成功查找** | 找到 / 未找到满足条件的记录 |
| **内部查找 / 外部查找** | 查找表全部在内存 / 需访问外存 |
| **平均查找长度（ASL）** | 查找过程中**关键字比较次数的期望值**：**ASL = Σ pᵢ·cᵢ**（pᵢ 为查找第 i 个记录的概率，cᵢ 为找到它所需的比较次数） |

### （二）领会

**1. 查找算法的适用条件**
| 方法 | 对存储的要求 | 对有序性的要求 |
|---|---|---|
| 顺序查找 | 顺序存储或**链式存储**皆可 | **不需要有序** |
| 折半查找 | **必须顺序存储**（需随机访问） | **必须有序** |
| 分块（索引顺序）查找 | 顺序存储 + 索引表 | **块间有序、块内可无序** |
| 二叉查找树 / AVL / B 树 | 链式（或顺序模拟） | 按 **BST 性质**组织 |
| 哈希查找 | 顺序存储（散列表） | 不需要有序，但依赖**哈希函数** |

**2. 查找长度的含义**：ASL 是**比较次数的平均值（期望值）**，用于衡量查找算法的**时间性能**；分**成功查找的 ASL** 与**不成功查找的 ASL**（后者常用于哈希表评价）。ASL 越小越好；通常假设**等概率**查找 pᵢ = 1/n。

## 三、顺序表的查找

### （一）识记

| 术语 | 含义 |
|---|---|
| **顺序表** | 用连续单元存储记录的表（可随机访问） |
| **顺序查找（线性查找）** | 从表的一端开始**逐个比较**关键字 |
| **折半查找（二分查找）** | 每次与查找区间的**中间位置**元素比较，逐步把区间缩小一半 |
| **折半查找判定树** | 描述折半查找过程的**二叉判定树**（每个结点对应一次比较） |
| **索引** | 由"分块最大（小）关键字 + 起始地址"构成的表 |
| **索引顺序查找（分块查找）** | 先查索引确定所在块，再在块内顺序查找 |

### （二）领会

**1. 顺序查找的适用条件**：表**无序或有序**皆可；**顺序存储或链式存储**皆可；实现简单，适合**表小或查找不频繁**的场合；可用**哨兵（监视哨）** 免去越界判断。
- **成功 ASL = (n+1)/2**（等概率：Σi/n = (1+2+…+n)/n）；
- **不成功 ASL = n + 1**（带哨兵时比较 n+1 次；不带哨兵为 n 次 ⚠️ 视教材）；
- 时间复杂度 **O(n)**。

**2. 折半查找的适用条件（必考）**：**必须是有序表**，且**必须采用顺序存储（能随机访问）**；链式存储无法直接折半（可改用跳表/树结构）。复杂度 **O(log₂n)**。

### （三）简单应用（ASL 计算，必考）

**1. 顺序查找 ASL**
- 成功：**ASL = (n+1)/2**（n=10 → 5.5）；
- 不成功：**n + 1**。

**2. 折半查找：判定树与 ASL**
- **判定树高度（查找成功时的最大比较次数）h = ⌊log₂n⌋ + 1**（等价于 ⌈log₂(n+1)⌉）；
- 等概率成功 ASL：设判定树第 i 层有 2^(i−1) 个结点（满树 n = 2ʰ−1 时）
  **ASL = (1/n)·Σ_{i=1}^{h} i·2^(i−1) = ((n+1)/n)·log₂(n+1) − 1 ≈ log₂(n+1) − 1**
- **计算示例（n = 11）**：判定树各层结点数为 **1、2、4、4**
  ASL = (1×1 + 2×2 + 3×4 + 4×4)/11 = (1 + 4 + 12 + 16)/11 = **33/11 = 3**
  即平均约 **3 次**比较，最大比较次数 = 树高 = **4**（⌊log₂11⌋+1 = 4）。
  ```
                6                ← 第1层（mid = ⌊(1+11)/2⌋ = 6）
             /     \
            3       9            ← 第2层
          /  \    /  \
         1    4  7   10          ← 第3层
          \    \  \    \
           2    5  8   11        ← 第4层
  ```

**3. 分块查找（索引顺序查找）ASL 与最优配置**
- 表分 **b 块**、每块 **s 个**记录（**块内无序、块间有序**），索引表存每块**最大关键字**与**起始地址**；
- 索引查找用顺序查找时：**ASL = (b+1)/2 + (s+1)/2**；
- **最优配置**：由 `b = n/s` 代入，当 **s = √n（即块数 b = √n）时 ASL 最小**，**ASL ≈ √n + 1**；
- 例：n = 100，s = b = 10 → ASL = (10+1)/2 + (10+1)/2 = **11**（≈√100 + 1）。
> 若索引表用**折半查找**，则 ASL ≈ ⌈log₂(b+1)⌉ + (s+1)/2。

## 四、树形结构的查找

### （一）识记

| 术语 | 含义 |
|---|---|
| **二叉查找树（BST）** | 或为空，或满足：**左子树所有结点关键字 < 根 < 右子树所有结点关键字**，左右子树也都是 BST |
| **BST 的特性** | **中序遍历得到递增有序序列**；查找路径唯一；不含相同关键字（可约定） |
| **查找过程中关键字比较序列** | 从根开始的比较关键字序列（如查找 37：45 → 24 → 37） |
| **AVL 树（平衡二叉树）** | 任一结点的**左右子树高度差的绝对值 ≤ 1** 的二叉查找树 |
| **平衡因子（BF）** | 结点左子树高度 − 右子树高度，取值 **−1、0、1** |
| **B 树** | 一种**多路平衡查找树**：m 阶 B 树的每个结点最多 **m** 棵子树、**m−1** 个关键字，所有叶结点在**同一层**（绝对平衡） |

### （二）领会

**1. 二叉查找树基本操作的过程**
- **查找**：与根比较 → 小于走左、大于走右、相等成功；走到空即**查找失败**。比较次数 ≤ **树高**；
- **插入**：先按查找走到**空位置**，把新结点作为**叶结点**插入（BST 的插入总是插在叶子处）；
- **生成树形**：由初始序列**依次插入**决定；**插入顺序不同 → 树形不同**。

**2. 树形与查找效率的关系**
- 最好情况：树**接近平衡**（完全二叉树形态），树高 = **⌊log₂n⌋+1**，查找 **O(log₂n)**；
- 最坏情况：插入序列**有序** → 退化为**单支树**（相当于链表），树高 = n，查找 **O(n)**；
- 结论：**BST 的查找效率取决于树高（形态）**；为保持高效需**动态平衡**（AVL 树、红黑树、B 树）。

**3. 二叉查找树的插入、查找与删除（删除是难点）**
删除结点 p 分三种情况：
① **p 是叶子** → 直接删除（把父结点的相应指针置空）；
② **p 只有左子树或只有右子树** → 用**其唯一的子树顶替** p（"子承父业"）；
③ **p 左右子树都有** → 用它的**中序前驱（左子树中最大者）** 或 **中序后继（右子树中最小者）** 的**值替换** p 的值，然后按 ① 或 ② 删除那个前驱/后继结点。

**删除示例**：依次插入 45, 24, 53, 12, 37, 93 建成 BST（中序：12, 24, 37, 45, 53, 93）
```
        45
       /  \
     24    53
    /  \     \
   12   37    93
```
**删除 24**（左右子树都有）→ 用中序前驱 **12** 或中序后继 **37** 顶替：
用 37 顶替后：
```
        45
       /  \
     37    53
    /        \
   12         93
```
（中序：12, 37, 45, 53, 93）

**4. B 树的查找、插入与结点分裂过程**
- **B 树的查找**：在结点内用**顺序查找或折半查找**关键字；若命中则成功；否则沿相应指针下移到孩子结点继续（直到叶结点为空 → 失败）；
- **B 树的插入**：总是插入到**最底层的叶结点**；若插入后该结点**关键字个数 > m−1（溢出）** → **分裂**：
  取**中间关键字**（第 ⌈m/2⌉ 个）**上移到父结点**，其余左右两半分别构成**两个新结点**；
  若父结点也溢出，则**继续向上分裂**（可能直到根分裂 → 树高 +1）；
- **绝对平衡**：B 树所有叶结点在同一层，因此查找路径长度相同，效率稳定。

**B 树插入分裂示例（3 阶 B 树，每个结点最多 2 个关键字）**
```
插入 1     →  [1]
插入 2     →  [1 2]
插入 3     →  [1 2 3] 溢出 → 中间 2 上移 → 根[2]，左[1]，右[3]
插入 4     →  最右叶 [3 4]
插入 5     →  [3 4 5] 溢出 → 中间 4 上移 → 根[2 4]，三叶 [1] [3] [5]
```

### （三）简单应用

**1. 二叉查找树基本操作实现（类 C）**
```c
typedef struct BSTNode { int key; struct BSTNode *lchild, *rchild; } BSTNode, *BSTree;

BSTNode *Search(BSTree T, int k) {                 // 查找
    while (T && T->key != k) T = (k < T->key) ? T->lchild : T->rchild;
    return T;                                       // NULL 即查找失败
}
int Insert(BSTree *T, int k) {                      // 插入（递归）
    if (!*T) { *T = (BSTNode*)malloc(sizeof(BSTNode));
               (*T)->key = k; (*T)->lchild = (*T)->rchild = NULL; return 1; }
    if (k == (*T)->key) return 0;                   // 已存在，不插
    return (k < (*T)->key) ? Insert(&(*T)->lchild, k) : Insert(&(*T)->rchild, k);
}
int Delete(BSTree *T, int k) {                      // 删除（难点，三种情况）
    if (!*T) return 0;
    if (k < (*T)->key) return Delete(&(*T)->lchild, k);
    if (k > (*T)->key) return Delete(&(*T)->rchild, k);
    BSTNode *p = *T;
    if (!p->lchild)       *T = p->rchild;           // ② 只有右子树（含叶子）
    else if (!p->rchild)  *T = p->lchild;           // ② 只有左子树
    else {                                          // ③ 左右都有：用中序前驱顶替
        BSTNode *s = p->lchild;
        while (s->rchild) s = s->rchild;            // 找左子树最大者
        p->key = s->key; Delete(&p->lchild, s->key);// 递归删除前驱
    }
    free(p); return 1;
}
```

**2. AVL 树的旋转（四种情况，必考）**
| 类型 | 触发情形 | 调整方法 |
|---|---|---|
| **LL** | 新结点插在**左子树的左侧** | **右单旋**（以最小不平衡子树的根为轴） |
| **RR** | 新结点插在**右子树的右侧** | **左单旋** |
| **LR** | 新结点插在**左子树的右侧** | **先左旋（对左孩子）再右旋（对根）**（双旋） |
| **RL** | 新结点插在**右子树的左侧** | **先右旋（对右孩子）再左旋（对根）**（双旋） |

**旋转示例（LR 型）**：依次插入 **16, 3, 7**
- 插入 16、3（3 为 16 的左孩子）；插入 7：7 > 3 → 作为 3 的**右孩子** → 结点 16 的 BF = 2（左高 2、右高 0）→ **LR 型**；
- **先对 3 左旋** → 3 的右孩子 7 上升；**再对 16 右旋** → 结果：
```
        7
      /   \
     3     16
```
（其余：插入 3,2,1 → **LL** → 右单旋 → 根 2；插入 1,2,3 → **RR** → 左单旋 → 根 2；插入 3,5,4 → **RL** → 双旋 → 根 4）

**3. 树形查找效率分析**：BST 查找长度 = 树高（最好 ⌊log₂n⌋+1、最坏 n）；AVL 树/B 树查找长度 = **O(log₂n)**（AVL 树高 ≤ 约 1.44log₂n；m 阶 B 树高 ≈ log_m n）；**AVL 树插入/删除需 O(log n) 次旋转以内**。

### （四）综合应用
① 由无序序列构造 BST 并写出树形/中序序列；② 判断给定树是否为 BST/AVL；③ 求查找某关键字的比较序列；④ 计算 BST 的 ASL（等概率：(1/n)Σ(结点所在层数)）；⑤ 用 AVL 树维持动态有序表；⑥ B 树/B+ 树用于**文件索引与数据库**（减少外存访问次数）。

## 五、哈希表及其查找

### （一）识记

| 术语 | 含义 |
|---|---|
| **哈希表（散列表）** | 由哈希函数与冲突处理方法把关键字映射到存储位置的查找表 |
| **哈希函数 H(k)** | 由关键字**直接计算存储地址**的函数 |
| **哈希地址** | H(k) 计算出的存储位置 |
| **冲突（碰撞）** | 不同关键字计算出**相同哈希地址**的现象 |
| **同义词** | 具有**相同哈希地址**的不同关键字（彼此互为同义词） |
| **完美哈希函数** | **不产生任何冲突**的哈希函数（理想情况） |
| **基本聚集（一次聚集）** | **线性探测法**中，连续被占用的单元形成"堆积"，使后续冲突概率与探测长度增大 |
| **二级聚集** | **二次探测法**中，同义词按相同探测序列探测所形成的聚集 |
| **装填因子 α** | **α = 表中记录数 n / 表长 m**（衡量表的"满"程度；α 越大冲突越多） |
| **查找成功的 ASL / 不成功的 ASL** | 成功查找的比较次数平均值 / 查找不存在的关键字时的比较次数平均值（按 m 个地址平均） |

### （二）领会

**1. 哈希函数的构造方法（6 种）**
| 方法 | 说明 |
|---|---|
| **直接定址法** | H(k) = a·k + b（线性函数），不产生冲突，适合关键字连续、分布已知 |
| **数字分析法** | 选取关键字中**分布均匀的若干位**作哈希地址（如学号后 4 位） |
| **平方取中法** | 取 k² 的**中间若干位**作哈希地址（中间位受各位影响大） |
| **折叠法** | 把关键字**分割成若干段相加**（可移位叠加/间界叠加） |
| **除留余数法** | **H(k) = k mod p**，p 通常取**不大于表长 m 的质数**（最常用） |
| **基数转换法** | 把关键字按另一基数转换后取位（如按 13 进制转换） |
| （随机数法） | H(k) = random(k)，适合关键字长度不等 |

**2. 冲突解决方法（4 类）**
| 方法 | 做法 | 特点 |
|---|---|---|
| **开放地址法** | **H_i = (H(k) + d_i) mod m**，在表内寻找空闲单元 | 无需额外空间；但会产生聚集 |
| 　**线性探测法** | d_i = 1, 2, 3, …（顺序后移） | 简单；产生**基本聚集**，探测长度增长快 |
| 　**二次探测法** | d_i = 1², −1², 2², −2², … | 减轻基本聚集，但有**二级聚集** |
| 　**伪随机探测/再散列** | d_i 由伪随机序列或另一哈希函数给出 | 聚集更少 |
| **链地址法（拉链法）** | 把所有**同义词**链成一条**单链表**，表头存各哈希地址 | **不产生聚集**；适合表长不确定；可插入删除 |
| **公共溢出区法** | 冲突的记录一律放入公共溢出区 | 简单，适合冲突很少的情况 |
| **再哈希法（双散列）** | 冲突时用**另一个哈希函数**再算地址 | 不易聚集，计算量增加 |

**3. 影响哈希方法效率的因素**
① **哈希函数是否均匀**（分布越均匀冲突越少）；
② **冲突处理方法**（链地址法一般优于线性探测）；
③ **装填因子 α**（**最主要因素**：α 越大冲突越多、ASL 越大）；
④ 关键字集合的特点；
⑤ 表长 m 与 p 的选取（p 取质数）。

### （三）简单应用（建立哈希表与 ASL 计算，必考）

**1. 建立哈希表（线性探测法）**
关键字序列 `19, 14, 23, 1, 68, 20, 84, 27, 55, 11, 10, 79`，表长 **m = 13**，**H(k) = k mod 13**：

| 关键字 | H(k) | 探测过程 | 比较次数 | 最终地址 |
|---|---|---|---|---|
| 19 | 6 | 直接放入 | 1 | 6 |
| 14 | 1 | 直接放入 | 1 | 1 |
| 23 | 10 | 直接放入 | 1 | 10 |
| 1 | 1 | 1 被占（14）→ 2 空 | 2 | 2 |
| 68 | 3 | 直接放入 | 1 | 3 |
| 20 | 7 | 直接放入 | 1 | 7 |
| 84 | 6 | 6（19）→ 7（20）→ 8 空 | 3 | 8 |
| 27 | 1 | 1、2、3 占 → 4 空 | 4 | 4 |
| 55 | 3 | 3（68）→ 4（27）→ 5 空 | 3 | 5 |
| 11 | 11 | 直接放入 | 1 | 11 |
| 10 | 10 | 10（23）→ 11（11）→ 12 空 | 3 | 12 |
| 79 | 1 | 1→9 依次被占 → 9 空 | 9 | 9 |

**哈希表（地址 0–12）**：0 空 | 1:14 | 2:1 | 3:68 | 4:27 | 5:55 | 6:19 | 7:20 | 8:84 | 9:79 | 10:23 | 11:11 | 12:10
**成功 ASL = (1+1+1+2+1+1+3+4+3+1+3+9)/12 = 30/12 = 2.5**
**不成功 ASL**（按哈希地址 0…12 各自探测到第一个空单元的比较次数平均）
= (1 + 13 + 12 + 11 + 10 + 9 + 8 + 7 + 6 + 5 + 4 + 3 + 2)/13 = **91/13 ≈ 7**
> 对比：**装填因子 α = 12/13 ≈ 0.92**（很满）→ 说明**线性探测在 α 较大时性能急剧下降**（基本聚集严重）。

**2. 用链地址法处理同一组关键字（H(k) = k mod 13）**
```
1 : 14 → 1 → 27 → 79
3 : 68 → 55
6 : 19 → 84
7 : 20
10: 23 → 10
11: 11
```
比较次数：14(1)、1(2)、27(3)、79(4)、68(1)、55(2)、19(1)、84(2)、20(1)、23(1)、10(2)、11(1)
**成功 ASL = (1+2+3+4+1+2+1+2+1+1+2+1)/12 = 21/12 = 1.75**（优于线性探测的 2.5）
> 链地址法的期望 ASL ≈ **1 + α/2**（成功）；不成功 ASL ≈ **α**（或 1+α，视约定 ⚠️）。

**3. 哈希查找的特点**
- 理想情况下**查找、插入、删除的平均时间都是 O(1)**（与表长 n 无关，只看 α）；
- 哈希表**不支持范围查找**、不支持有序遍历（要保持有序需另建索引）；
- 设计时**兼顾 α 与冲突处理方法**：α 一般控制在 0.5–0.75（开放地址法）或 1 左右（链地址法）。

## 六、本章对比与易混点

### 1. 各查找方法对比（必背）

| 查找方法 | 存储要求 | 有序要求 | 平均查找长度 ASL | 时间复杂度 | 适合 |
|---|---|---|---|---|---|
| **顺序查找** | 顺序或链式 | 不需有序 | 成功 **(n+1)/2** | O(n) | 表小/无序/链式 |
| **折半查找** | **必须顺序存储** | **必须有序** | ≈ **log₂(n+1) − 1** | O(log₂n) | 有序表、查询频繁、表可随机访问 |
| **分块（索引顺序）查找** | 顺序存储 + 索引表 | 块间有序、块内无序 | **(b+1)/2 + (s+1)/2，最优 ≈ √n + 1** | O(√n) | 表大且分块组织、动态插入较多 |
| **二叉查找树** | 链式 | 按 BST 性质 | 与**树高**有关（≈log₂n ~ n） | 最好 O(log₂n)、最坏 O(n) | 动态查找表 |
| **AVL 树** | 链式 | BST + 平衡 | **O(log₂n)** | 稳定 O(log₂n) | 频繁查找+插入删除、要求最坏也快 |
| **B 树 / B+ 树** | 外存块结构 | 多路平衡 | **O(log_m n)** | 稳定 | **外存索引（数据库/文件系统）** |
| **哈希（散列）查找** | 顺序存储（散列表） | 不需有序 | 与 **α** 有关（如 1+α/2） | 平均 **O(1)** | 只做精确查找、不需要范围/顺序访问 |

### 2. 易混点

| 易混点 | 正确理解 |
|---|---|
| **折半查找的条件** | **必须有序 + 必须顺序存储（随机访问）**；链式不能直接折半 |
| 折半判定树的高度 vs ASL | 高度 = **最大比较次数** = ⌊log₂n⌋+1；ASL 是**平均比较次数** ≈ log₂(n+1) − 1 |
| 顺序查找「不成功」 | 需比较到表尾（**n 或 n+1 次**），远大于成功时的 (n+1)/2 |
| 分块查找的最优块长 | **s = √n**（块数与块长相等时 ASL 最小 ≈ √n + 1） |
| **BST 的插入位置** | 新结点总是插到**叶子**处（查找失败的位置） |
| BST 删除的两种情况 | 单子树 → **子树顶替**；双子树 → **中序前驱/后继顶替后删除该结点** |
| BST 的效率 | 取决于**树高（形态）**；有序插入 → 退化为**单支树 O(n)** |
| **AVL 平衡因子** | BF = **左子树高 − 右子树高**，只能取 **−1、0、1** |
| LL/RR/LR/RL | LL→**右单旋**；RR→**左单旋**；LR→**先左后右**；RL→**先右后左** |
| B 树阶数 m | 每个结点**最多 m 棵子树、m−1 个关键字**；根至少 2 棵子树；非根非叶至少 **⌈m/2⌉** 棵子树 |
| **B 树分裂** | **中间关键字上移父结点**，左右两半成两个结点；可能**向上传播**甚至增加树高 |
| B 树 vs 二叉查找树 | B 树**多路、绝对平衡**（所有叶同层）；适合**外存**（减少 I/O 次数） |
| 哈希冲突 | 不同关键字算出**同一地址**（≠ 同义词本身，同义词是"哈希地址相同"的关键字） |
| **基本聚集 vs 二级聚集** | 基本聚集来自**线性探测**（连续占用成片）；二级聚集来自**二次探测**（同义词探测序列相同） |
| 哈希查找效率 | 主要取决于**装填因子 α** 与冲突处理方法，而**不是**表长 n；理想 O(1) |
| 链地址法优势 | **不产生聚集**、可动态插入删除、适合 α 接近或超过 1 |
| 哈希表能否范围查找 | **不能**（不支持有序遍历）；范围查找需用有序表/B 树/B+ 树 |

### 3. 公式速记
| 公式 | 说明 |
|---|---|
| **ASL = Σ pᵢ·cᵢ** | 平均查找长度（等概率时 pᵢ = 1/n） |
| **顺序查找：成功 (n+1)/2；不成功 n+1（或 n）** | 顺序查找 |
| **折半：h = ⌊log₂n⌋ + 1；ASL ≈ log₂(n+1) − 1** | 折半查找 |
| **分块：ASL = (b+1)/2 + (s+1)/2；最优 s = b = √n → ASL ≈ √n + 1** | 分块查找 |
| **BST 查找长度 = 树高**（最好 ⌊log₂n⌋+1、最坏 n） | BST |
| **AVL 树高 ≈ 1.44 log₂n**；B 树高 ≈ log_m n | 平衡树 |
| **α = n / m**；链地址法成功 ASL ≈ 1 + α/2 | 哈希表 |

### （三）计算题模板
1. **顺序查找**：成功 ASL = (n+1)/2；不成功 = n+1。
2. **折半查找**：画判定树（每次取 mid）→ 统计各层结点数 → ASL = Σ(层数×该层结点数)/n；最大比较次数 = 树高 = ⌊log₂n⌋+1。
3. **分块查找**：ASL = (b+1)/2 + (s+1)/2；由 n = b·s 与均值不等式求最优 **s = b = √n**。
4. **BST**：按序列依次插入画树 → 中序验证 → 删除按三种情况处理 → ASL = Σ(结点层数)/n。
5. **AVL**：插入后从插入点向上找**最小不平衡子树** → 判断 LL/RR/LR/RL → 旋转 → 验证 BF。
6. **B 树**：逐次插入 → 溢出（关键字数 > m−1）→ **中间关键字上移**、左右分裂，必要时向上传播。
7. **哈希表**：按 H(k) 计算地址 → 冲突时按探测序列（线性：+1,+2,…；二次：±1²,±2²…）逐个试放 → 列表记录比较次数 → **成功 ASL = Σcᵢ/n**；**不成功 ASL = Σ(各地址探测到空的次数)/m**；α = n/m。
